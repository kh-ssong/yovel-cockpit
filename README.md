# yovel-cockpit

> 사용자 PC 에서 도는 **집행 데몬** + 데스크톱 셸. 판단은 서버가 하고, 주문은 여기서 나간다.

```
yovel-pitwall    서버 · 통합 의사결정      F1 피트월 = 데이터 보고 전략만 짜는 지휘석   (비공개)
yovel-cockpit    클라 · 공개형 집행기      조종석 = 사용자가 앉는 자리                 ← 이 저장소
yovel-flat6      독립 · 초단타 스캘핑      엔진 = 무전 안 기다리고 혼자 돎             (비공개)
```

---

## 상태

★ **설계 단계 — 실행 코드 없음.** 현재 이 저장소에 있는 것은 설계 계약과 위생 설정뿐이다.
아래 「네트워크 계약」은 구현할 때 지킬 **약속**이지, 지금 그렇게 동작한다는 서술이 아니다.
코드가 들어오면 이 문단을 지운다.

와이어 프로토콜 계약 = **[`docs/protocol.md`](docs/protocol.md)** + [`schema/v1/`](schema/v1)
(JSON Schema, `cd schema && npm test` 로 예제 검증).

## 1. 왜 공개인가

이 프로그램은 **증권사 API 키를 직접 다룬다.** 그게 공개의 유일한 이유다.

"키는 당신 PC 를 떠나지 않습니다" 라고 말하는 건 쉽다. 문제는 사용자가 그걸 **확인할 방법**이다.
서버가 매번 새 코드를 내려주는 구조(웹앱·자동 갱신 스크립트)라면 그 약속은 내가 언제든, 조용히
깰 수 있고 사용자는 알 수 없다. 신뢰를 말로 하지 않으려면 **키를 만지는 쪽을 열어두는 것** 말고는 없다.

그래서 경계가 여기다: **키를 만지는 절반은 공개, 전략(pitwall)은 비공개.**

## 2. 네트워크 계약 (구현 목표)

| 나가는 곳 | 방향 | 용도 | API 키 |
|---|---|---|---|
| 증권사 REST / WebSocket | 이 PC → 증권사 | 시세 조회, 주문 | **사용** (이 PC 안에서만) |
| yovel 릴레이 (WSS 443) | 이 PC → 서버 (아웃바운드) | 신호 수신, 상태 보고 | **없음** |

그 외 어디에도 접속하지 않는다. 인바운드 포트를 열지 않으므로 공유기 설정도 필요 없다.

**절대 나가지 않는 것**: API 키 · 시크릿 · 계좌번호.

**서버에서 내려오는 것**: 포지션별 `stop_price` / `tp_price` / 유효시각. 숫자뿐이고 **전략 산식은 오지 않는다.**
따라서 이 저장소를 다 읽어도 전략은 복원되지 않는다 — 그게 이 분리가 성립하는 이유다.

**★ "서버" 는 하나가 아니라 둘이다** — 여기가 이 설계의 핵심이라 정확히 쓴다.

| | 할 수 있는 것 | 털리면 최악 |
|---|---|---|
| **pitwall** (전략 · 서명키) | 진입 포함 전체 지시 | 진짜 사고. 그래서 서명키는 릴레이에 두지 않는다 |
| **yovel 릴레이** (중계) | 중계 · 지연 · 드롭 · de-risk | **봇이 꺼짐** — 복구 가능 |

진입 지시는 **pitwall 서명키(Ed25519)로 서명된 것만** 유효하고, 클라는 그 공개키를 바이너리에
pin 한다. 릴레이는 암호문을 나르기만 하므로 **릴레이를 장악해도 "사라"를 지어낼 수 없다.**
릴레이가 자기 권한으로 보낼 수 있는 건 de-risk(전량청산 · 일시정지 · 신규진입차단)뿐이다.

★ 계약 검증기의 `examples/invalid/` 에 이 두 성질이 **깨지면 CI 가 빨개지는 형태**로 박혀 있다
(서명 없는 진입 · 명령 채널의 `buy`).

## 3. 구조

```
[데몬]      OS 서비스로 상주 (Windows Service / launchd)
              ↑ localhost API + 토큰 인증
[Tauri 셸]  순수 UI. 열었다 닫았다 자유 — 닫아도 데몬은 계속 돈다
```

★ UI 를 데몬의 사이드카로 두지 않는다. 사이드카는 창을 닫으면 프로세스를 같이 죽이는데,
이 봇이 일하는 시간이 하필 **사용자가 화면을 안 보는 시간**(장 시작 직후, 새벽)이다.
같은 이유로 브라우저 웹앱도 불가 — 탭을 닫으면 사망하고, 백그라운드 탭은 타이머가 스로틀된다.

## 4. 끊겨도 안전한 이유 — exit 3층

> 진입 실패는 기회 상실(유한)이지만, **청산 실패는 손실 노출(무한)** 이다.
> 그래서 청산은 네트워크에 의존하지 않는 쪽으로 층을 내린다.

| 층 | 담당 | 네트워크 끊기면 |
|---|---|---|
| 브로커 위임 (지정가 · 조건부 주문) | 익절 | **그대로 체결됨** — 데몬도 서버도 죽어도 무관 |
| 클라 로컬 | 손절 · 시간청산 · 데드맨 | **그대로 동작** — 마지막으로 받은 stop 가격이 유효 |
| 서버 명령 | 포트폴리오 디그로스 · 긴급 de-risk | 안 옴 (로컬로 표현 불가능한 것만 여기 둠) |

연결이 끊기면 트레일링 stop 이 **따라 올라가지 못할 뿐**이다. 최악이 "덜 잘 판 것" 이지 무방비가 아니다.

## 5. 알려진 제약

- **PC 가 꺼지면 돌지 않는다.** 24 시간 시장을 다루려면 PC 상시 가동이나 소형 서버가 필요하다.
- macOS 는 사용자 로그인 후에 데몬이 뜬다(관리자 권한을 안 쓰는 대가). 새벽 재부팅 시 공백이 생길 수 있어,
  **연결 끊김 알림**을 기능이 아니라 안전장치로 취급한다.
- 모바일 앱은 계획에 없다. 폰은 조회와 de-risk 전용이면 충분하고, 키를 만지지 않으므로 네이티브로
  굳힐 값어치가 없다.

## 6. 개발

```
cmd/cockpitd/        데몬 진입점
internal/protocol/   와이어 타입 + 서명 검증 + 수용 규칙   ← 계약의 Go 측 구현
internal/config/     로컬 설정 · pin 된 pitwall 공개키
internal/httpapi/    로컬 API (토큰 · Host · Origin 가드)
internal/version/    버전 · SHA (드리프트 감지)
docs/protocol.md     ★ 와이어 계약 SSOT
schema/v1/           ★ 같은 계약의 JSON Schema (npm test 로 예제 검증)
ui/                  Svelte SPA — 산출물 ui/dist 를 데몬이 서빙하다가 Tauri 가 번들 (미착수)
```

```bash
go test ./...            # Go
cd schema && npm test    # 계약 예제
scripts/build.sh cross   # macOS(arm64/amd64) + Windows + Linux 를 한 번에

./bin/cockpitd-<plat> --port 7737 --data-dir ./.cockpit
curl -H "Authorization: Bearer $(cat .cockpit/api-token)" http://127.0.0.1:7737/v1/health
```

- 데몬 언어 = **Go**. 이유는 성능이 아니라 크로스컴파일 — 윈도우 PC 한 대에서 macOS ARM/Intel 바이너리까지 낸다.
- ★ **빌드는 반드시 `scripts/build.sh` 로.** go 의 자동 VCS 스탬프는 **git worktree 에서 동작하지 않아**
  (`.git` 이 파일이라 감지 실패, `-buildvcs=true` 를 줘도 조용히 비운다) sha 가 `unknown` 이 된다.
  sha 가 비면 "업데이트했는데 옛 코드가 돌고 있음" 드리프트 감지가 통째로 죽는다.
- 브로커 드라이버는 증권사마다 **별도 파일**로 짓는다. 겉만 비슷하고 응답 스키마가 전부 달라서,
  섣부른 공통화는 한 증권사의 착각을 전 증권사로 번지게 한다.
- 릴리스 바이너리가 이 소스에서 나온 것인지 확인할 수 있도록 **재현 가능 빌드**를 목표로 한다
  (`-trimpath`, `CGO_ENABLED=0`). 그게 되어야 §1 의 공개가 말이 아니라 검증이 된다.
