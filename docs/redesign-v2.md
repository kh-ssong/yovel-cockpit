# 콕핏 v2 — 주문·잔고 관리자로 재설계

작성 2026-09-26 · 상태 **초안** · 근거 = 이 날 세션에서 드러난 구멍들 (아래 §0)

★ 콕핏을 매매 엔진과 분리한 이유는 **주문·잔고 관리를 독립적이면서 특화**하기 위해서다.
v1 은 "목표를 받아 주문을 내는 실행기" 까지는 왔지만, **돈을 관리하는 쪽**이 설정값 몇 개
(`--engine-budget`, `books.json`)로 때워져 있다. v2 는 그 쪽을 1급 개념으로 올린다.

---

## 0. v1 에서 드러난 것 (재설계의 입력)

| 증상 | 뿌리 |
|---|---|
| 주식·코인이 데몬 두 개, 총시드를 볼 곳이 없다 | 데몬 하나 = 브로커 하나 |
| 전략이 잃어도 한도가 그대로 | 장부가 **계좌**가 아니라 설정값 |
| Σ장부 시드 > 현금이어도 경고뿐 | 할당과 실제 현금이 연결 안 됨 |
| 부분체결 유령 · 죽은 TP 재취소로 청산 막힘 | 주문에 **상태 머신이 없다** (성공/실패 2값) |
| 체결가·시각 미상, `filled_at` 지연 | 체결을 폴링으로 **추정** (통지 없음) |
| 코인 paper 불가 | paper 가 거래소 규칙(단위·최소주문·수수료)을 모름 |
| stop · 15:20 시간청산 미발동 | 리스크 층(`internal/guard`)이 집행 루프 밖에 방치 |
| reflex 와 같은 계좌 공유 | 계좌 안 "남의 몫" 을 모델링 안 함 |

## 1. 결정 (2026-09-26 user)

1. **한 데몬 · 다계좌.** 키움 주식 · 업비트 코인 · paper 계좌들을 한 프로세스가 굴린다.
   총자본·장부·리스크를 한 곳에서 본다. 계좌별 장애 격리는 고루틴·타임아웃·서킷으로.
2. **장부 = 고정 사이즈 + 손익 누적.** 사이징 분모는 **시드 고정**(도장 원장과 같은 크기).
   현금 한도는 `시드 + 실현손익`. 리밸런싱(시드 조정)은 사람이 명시적으로 한다. 복리 아님.
3. **궁극적으로 콕핏이 유일한 주문자.** reflex 등 다른 봇도 결국 신호만 낸다.
   그 전까지 같은 계좌의 남의 보유는 `external` 장부로 격리한다.

## 2. 도메인 모델

```
Capital (사용자 총자본 — 계좌들의 합, 보기용)
 └─ Account           브로커 연결 1개. 실제 현금·보유의 SSOT.
     │                 kiwoom:<계좌> · upbit:<계좌> · paper:KRX · paper:UPBIT
     ├─ Book           전략 = 가상 하위계좌. 한 Book 은 한 Account 에만 속한다.
     │   ├─ Position   (intent 단위) ← Order ← Fill
     │   └─ Limits     일일손실 · 최대보유수 · 종목당 상한
     └─ Book:external  설명 안 되는 보유 (수동 · 다른 봇). 할당 가능 현금에서 뺀다.
```

- **Account 가 소유하는 것**: 자격증명·토큰(키움 1계정 1토큰), 속도 제한 버킷, 거래소 규칙
  (`lot`, `min_order`, 수수료, 호가단위, 장 시간), 현금 3층(예수금 / 주문가능 / 현금한도 L1).
- **Book 이 소유하는 것**: 시드, 원장에서 파생되는 현금·실현손익·보유, 한도, slot 매핑.
- **Market(거래소 규칙)은 Account 에서 나온다** — paper 도 같은 규칙표를 쓴다. v1 paper 의
  `Lot=1` 고정 같은 "paper 만의 규칙" 을 없앤다.

## 3. 돈의 산식

```
book.cash          = seed + realized − open_cost − fees_paid        (원장에서 파생)
book.sizing_base   = seed                                            (고정 — 도장 원장과 같은 크기)
order.qty          = floor(weight × book.sizing_base / ref_price / lot) × lot
order 허용 조건     = notional ≤ book.cash  AND  notional ≤ account.allocatable
account.allocatable = account.cash_L1 − Σ(다른 book 의 미체결 예약) − external 몫
할당 불변식         = Σ book.seed ≤ account.cash_L1 + Σ open_cost   (기동·리밸런싱 시 강제)
```

- **예약(reservation)**: 주문을 내는 순간 `book.cash` 에서 예약하고, 체결되면 실비용으로 확정,
  거부·취소되면 해제. 동시에 여러 장부가 들어와도(D-205 09:01 몰림) 계좌 현금을 이중으로 쓰지 않는다.
- 브로커 단 축소(키움 `kt00011`, 업비트 `chance`)는 **마지막 방어선**으로 남긴다 — 장부 산식이
  맞으면 거기서 줄어들 일이 거의 없어야 하고, 줄어들면 그게 드리프트 경보다.
- 불변식 위반 시 live 는 **기동 거부**(경고 아님), paper 는 경고.

## 4. 원장 — 이벤트 소싱

유일한 진실은 **주문·체결 이벤트 로그**다. 잔고·손익·한도는 전부 여기서 파생한다.

| 이벤트 | 내용 |
|---|---|
| `order.created` | book, intent, side, qty, 기준가, 예약액, 멱등키 |
| `order.submitted` | 브로커 주문번호, 제출 시각 |
| `order.fill` | 체결 수량·가격·수수료·시각 (**부분마다 한 줄**) |
| `order.terminal` | filled / cancelled / rejected(사유) / expired |
| `order.unknown` | 제출 결과 모름 (5xx·타임아웃) — 다음 대조가 확정할 때까지 예약 유지 |
| `book.adjust` | 시드 변경·입출금 (사람만) |
| `recon.drift` | 브로커 잔고 ↔ Σ장부 보유 차이 (external 로 귀속) |

- v1 의 `intents` 테이블(상태)과 `orders` 테이블(기록)이 갈라져서 생긴 버그들
  (부분체결 종결, `time_exit_at` 소실, 죽은 TP 번호)이 이 구조에선 **파생값이라 생기지 않는다.**
- mode(paper/live) 분리는 v1 규칙 그대로 — Account 가 paper 면 그 이벤트는 paper 다.

## 5. 주문 상태 머신

```
created ──submit──▶ submitted ──fill*──▶ partial ──fill*──▶ filled
   │                   │  │                  │
   │                   │  └──reject──▶ rejected        (예약 해제)
   │                   └──cancel──▶ cancelled           (체결분만 확정)
   └──submit 실패(5xx·타임아웃)──▶ unknown ──대조──▶ submitted | rejected
```

- **체결은 통지로 받는다.** 키움 WS `00`(주문체결) · 업비트 myOrder WS. 폴링은 통지가 끊겼을 때의 백업.
  → `filled_at` 이 실제 체결 시각이 되고, 도장 원장과 진입가·시각 대조가 가능해진다 (핸드오프 §4 콕핏-1·2).
  ★ 키움 WS 는 1계정 1세션이라 flat6 가 쥐고 있다 — **flat6 가 `00` 을 콕핏에 중계**하거나 콕핏이
  WS 를 소유하고 시세를 flat6 에 넘기거나, 둘 중 하나를 정해야 한다 (§9 미결).
- **멱등키**: 업비트 `identifier`, 키움은 주문번호 사후 매칭. `unknown` 상태에서 **같은 주문을 다시 내지 않는다.**
- 청산 주문은 걸린 TP 를 먼저 취소하고, 취소 결과도 이벤트로 남긴다.

## 6. 리스크 층 (콕핏 본업)

집행 루프 안에서 매 틱:

1. **포지션 규칙** — 시간청산(`time_exit_at`, 시세 불필요) · 로컬 stop(신선한 시세 있을 때만, 없으면 Blind 경보).
2. **장부 한도** — 일일 실현손실 한도 도달 → 그 장부 신규 진입 차단 (청산은 계속).
3. **계좌 한도** — 일일 손실 · 드리프트 · 브로커 연결 끊김 → 계좌 단위 진입 차단.
4. **데드맨** — 신호원(flat6) heartbeat 가 N 초 끊기면 설정에 따라 진입 차단 / 전량 청산.
5. **킬 스위치** — `cmd.derisk` + 로컬 UI 버튼. 계좌·장부·전체 범위.

★ 판단(언제 팔지)은 여전히 엔진 몫이다. 이 층은 **엔진이 없을 때를 위한 것**이다.

## 7. 시세

- 1순위: 엔진이 목표에 실은 `mark_price` (v1 에 이미 추가됨, 키 없이 동작).
- 2순위: 콕핏 자체 피드 — 업비트 공개 WS(키 불필요) 먼저, 키움은 키 여유가 생기면.
- 시세는 **평가·paper 체결·stop 에만** 쓴다. 사이징은 `ref_price`(신호가) — v1 규칙 유지.
- 자체 피드가 쌓이면 캔들/틱 저장소로 확장 (전략 사후 검증용).

## 8. paper

- paper 는 **Account 종류 하나**일 뿐이다: `paper:KRX`, `paper:UPBIT`. 규칙표(단위·최소주문·수수료·호가)는
  실계좌와 같은 것을 쓰고, 체결만 시뮬레이션한다 (mark → 슬리피지).
- 부분체결·거부·지연도 시뮬레이션 옵션으로 — v1 에서 부분체결 버그를 합성 브로커로 잡았다.
- 같은 전략을 paper 와 live 에 **동시에** 걸 수 있다 (다른 Book, 같은 slot → 매핑이 Account 별).

## 9. 엔진 계약 (변경 최소)

- `intent.target` 그대로. `slot` → Book 매핑은 콕핏 설정 (Account 별).
- `weight` 의미 = **장부 시드 대비** 한 자리 크기 (v1 §7.1.3 과 같음).
- 추가 요구: `mark_price` 싣기 (이미 규격), heartbeat (데드맨용 — 없으면 목표 발행 시각으로 대신).

## 10. 결정 · 미결

**결정 (2026-09-26 user)**

1. **키움 WS 는 콕핏이 소유한다.** 콕핏은 제3자가 **자기 키**로 쓰는 제품이다 — 계좌 WS(체결통지)는
   그 키의 주인인 콕핏 것이고, 엔진(flat6)은 사용자의 키를 볼 수도 없어야 맞다.
   ★ 지금은 키가 모자라 flat6 와 토큰을 공유하는 **임시 상태**다. 키를 하나 더 발급받으면 콕핏 전용으로 분리한다.
2. **설정은 둘로 나눈다.**
   - **돈(시드·한도·리밸런싱) = DB, 원장 이벤트로.** 시드 변경은 설정 수정이 아니라 **입출금 사건**
     (`book.adjust`)이다 — 파일 값으로 두면 바꾸는 순간 과거 수익률 분모가 조용히 틀어진다.
     UI 에서의 조정도 이 경로.
   - **기동 설정(계좌 종류·키를 읽을 환경변수·포트·data-dir) = 작은 파일/플래그.** 이력이 필요 없다.
     키 값 자체는 파일에 두지 않는다 (환경변수 / OS 키체인).
3. **external 귀속은 당분간 안 한다.** 콕핏이 모르는 보유는 세지도, 팔지도 않는다. 다른 봇이 쓴 돈은
   계좌 현금이 줄어드는 것으로 할당 한도에 자연히 반영된다. (§2 의 `Book:external` 은 보류)
4. **데드맨 = 진입만 차단.** 신호원이 끊기면 신규 진입을 막는다. 보유 청산은 시간청산·stop·사람 몫.
5. **UI 는 나중.** API(`/v1/books` 등)가 먼저.

**미결** — 없음 (새로 생기면 여기에).

## 11. 이행 순서 (각 단계 동작 유지)

| 단계 | 내용 | 끝나면 되는 것 |
|---|---|---|
| 1 | 이벤트 원장 + 주문 상태 머신 (단일 계좌 그대로) | 부분체결·unknown 이 구조적으로 안전 |
| 2 | Account 추상화 + 거래소 규칙표, paper 를 Account 로 | 코인 paper, 거래소별 수수료 |
| 3 | Book = 가상계좌 (예약·실현손익·한도), 할당 불변식 | 전략별 시드 관리 완성 |
| 4 | 다계좌 한 데몬 (키움+업비트+paper 동시) | 총자본 한 화면 |
| 5 | 리스크 층 배선 (시간청산·stop·일일한도·데드맨) | 라이브 전제 조건 충족 |
| 6 | 체결 통지 (WS) · 자체 시세 피드 | 도장 원장 대조 정밀도 |

★ 단계 5 중 **시간청산·로컬 stop 은 v1 에 먼저 배선했다** (2026-09-26, `internal/executor/local_exit.go`).
남은 것은 일일 손실 한도·데드맨(신호원 끊김 → 진입 차단)·킬 스위치 범위.
